# 法考学习最小实现设计

更新于 2026-11-19。本文记录已接通的法考短练、尚未实现的较长演练和验证边界。试用见[操作说明](courtroom-preview-and-tryout.md)，修复前的问题和取舍见[架构审查](legal-learning-architecture-review.md)，下一步见[制作计划](../制作计划.md)。

## 1. 目标与范围

**用户已明确目标群体为法考学生。** 核心目标是帮助学生理解规则、区分易混概念、从事实中识别问题、独立完成选择题与主观论证。案件材料由系统提供即可，不要求学生先提交一个具体案件。

日常路径是先讲清规则，再视需要安排一个争点的短练；读案卷、先写判断、回应一个对手，再看答题反馈。2–5 分钟是设计目标，实测耗时和学习收益待验证。第 6 节保留较长演练设计，完整多角色庭审、跨模块错因和独立复习尚未实现。题库的旧受众文案和评分逻辑不属于本次短练接入范围。

本轮内置一份带正式法律出处的虚构合同案。其余主题的 AI 生成案例会显示来源；未附正式出处的案例只评议论证与材料使用，提示要核对的法律前提。结构校验与材料一致不能证明模型引用或结论正确。

## 3. 题库：已实现范围与后续设计

### 3.1 已实现

- 首页题库入口与题库页，支持 JSON 导入预览、重复题识别、新建、编辑、启用和停用。
- 初始无预置题；模型补题随课程与选题结果保存，不自动成为用户题库内容。
- 当前元数据为 topic 自由文本、tags、题型、难度、启用状态、sourceTitle、sourceUrl。
- 经典课程、Pro Quiz 与独立练习调用同一选题实现。按题型、难度和 topic/tag 是否包含在大纲文字中匹配，从列表选取结果。
- 足量取题，不足补缺口；没有搜索配置时可依据已有材料与模型生成。选题快照用于重试复用和同课程去重，补题故障尽量保留已有题。
- 题库以 owner 隔离；Quiz 的草稿、提交、反馈、重试状态通过已有 RuntimeStore 保存。

### 3.2 当前限制

- 法域、法律适用时间、考试年度、稳定考点 ID 和完整来源类型尚未成为选题硬约束。不能把当前关键词匹配描述为已完成法律版本过滤或语义 RAG。
- 编辑是同 ID 更新 JSONB，以 updatedAt 做并发冲突检查；旧课程保存副本，但没有独立的不可变 QuestionVersion 实体。
- 题干指纹只考虑题型及去空白题干，同题干不同选项、答案或年度口径并不能靠它可靠区分。
- 选题结果记录实际对应 legal_assessment_selections；作答使用通用 Quiz runtime attempt。历史文档中的 SelectionReceipt、QuestionVersion、Attempt 不应被理解为三张均已落地的法学专用表。
- 简答评分主要接收题面、学生答案、分值和可选 commentPrompt，尚未按保存的题目版本读取评分依据。手动编辑简答解析时会同步 commentPrompt，但生成、导入内容可以缺省。
- 来源部分通过解析文字呈现，没有完整的结构化法律出处、适用版本或纠错传播能力。
- 页面与生成提示的受众文案仍偏通用法学自学，尚未完成法考适配。

### 3.3 建议补强（尚未实现）

先围绕有限考点统一身份、资料与时间口径，保持自由文本展示和旧课兼容；先改进召回与覆盖评估，再决定是否增加向量检索。

将评分绑定到已保存题目或案例的参考要点，反馈指向学生原答案，并明确哪些内容尚未观察到。没有依据时保留待反馈状态，不用“互动流畅”代替法律分析正确。

扩展现有学习记录，关联考点、错因、提示使用与后续独立作答。前置 Quiz 到 PBL 已有按整场准确率校准 proficiency 的联系；应补相关性，避免无关考点或不稳定评分影响演练难度。结课概览当前只重新判选择题，主观题和演练需要分别呈现结果，暂不合成“通过概率”。

## 4. 从普通知识点到练习

普通问答优先解决疑问；适合用材料检验判断的问题，比如“合同解除有什么条件？为什么违约时不一定能要求全额退款？”，可以出现短练。查询定义、法条原文或明确不要练习时，沿用原讲解。经典生成和 Pro 安排的是课程场景；问答卡创建的是单独练习，学生不需要原课堂的编辑权限。

“主动加入”首先指系统能识别适合的活动、生成或推荐可开始的练习；不等于每次自动把学生拉出正在看的讲解。新建作者场景和学习者临时练习需要区分，避免让普通学习者拥有课程编辑权限或使课程不断增加重复页面。

错题后的变式题、独立主观题训练和较长综合训练是可评估的后续入口。观察学生是否愿意点击、有无等待过长、返回后能否独立答新题。推荐过密会让学生避开随堂提问，单看创建数或完成率容易导向错误的优化目标。

## 5. 演练的职责与运行安排

### 5.1 短时演练的当前安排

- 固定一个争点，提供足够判断的小案情与共同材料，不照搬所有庭审程序。
- 学生先给判断与理由；对手进行有针对性的反驳；学生修正或坚持并说明依据。
- 导师使用独立通道，建议不自动作为学生发言。记录提示使用，避免把复述导师答案算成独立掌握。
- 最后要求中立的独立答案，反馈法律规则、事实适用和遗漏；可在返回课程后给变式题。
- 少量回合后允许完成、继续或退出；预算与完成进度不充当掌握判据。
- 开场、旁白与报告按短练目标压缩，验证从提问到首次可作答的实际耗时。

当前版本复用 PBL 的 prep → roleplay → wrapup、聊天记录和重练。短练使用固定开场，略过额外旁白；答题直接写到对话里，不要求上传作业。流程提示学生先判断、再回应，但不强制固定回合数。独立完成提示使用信号和变式题的关联仍为后续目标。

### 5.2 案件、角色与评价依据

优先解决共同材料同源：将固定案情、材料及引用、相关规则与反馈要点交给应接收它们的规划、对手、导师和评价调用。对手的主张与共同事实分开；未覆盖的信息明确未知，不临时补决定性事实。

当前角色对手不负责教学纠错，导师和评价承担解释。不能只给通用 Simulator 加“法官”名字；其现有职责明确是场内参与者。增加法官、证人或私有材料时才需要相应调度和可见性，不以图片席位数量决定 Agent 数量。

Skill 负责教 Pro 何时选择案例。结构化 `courtroomPractice` 把案例选择交给共有的生成器，材料写入课程设计快照，运行时再读取。固定案卷和参考要点要作为同一版本维护；修改决定性事实时增加案例 ID，避免旧课继续套用新答案。当前固定参考只在版本和材料均匹配时使用。

### 5.3 保存、返回与状态权威

复用现有 PBL 设计/学习者状态分离、runtime session、事件折叠与快照；对短练补必要关联与恢复行为。暂不把旧方案中的独立 TrialSession、expectedRevision、commandId 全套庭审命令系统视为首版前提。

若未来引入庭审专用状态，必须说明其与 PBL runtime 谁是权威、如何迁移或投影。不能两边分别推进同一场演练。刷新、断线、重试、重练与提前退出均需有确定行为；旧课程继续按原语义打开。

现有 API 仍用客户端项目执行学习状态变换；法庭对话与评价将其中的事实材料和角色设定换回服务端课程中的版本。这只把案卷定为服务端权威。独立练习会生成一个普通课堂，频繁推荐不同主题可能增加课程列表条目；先观察回访和恢复行为，再决定是否增加归档视图或更细的关联。

### 5.4 完整演练的后续条件

多争点、多角色、程序分支、证人、私有证据和披露控制属于综合训练需要确认的扩展。较长会话需要可引用的阶段证据，不能依赖最终评价仅保留的末尾 6000 字符。

完整演练的投入应由综合训练需求和学习收益支持，不作为让普通知识点进入短练的前置工程。

## 6. 较长合同演练底稿（设计样例，未接成运行时脚本）

本节保留 10–15 分钟、多环节的教学设计，时长不是法定庭审要求。短练已复用其中的 `contract-delivery-v1` 案卷，6.2 和 6.3 的多环节和角色行为仍是样例。训练区分交付约定、实际行为和主张，反馈允许有理由的不同观点。

### 6.1 固定底稿与共同材料

甲方为某学习工作室，乙方为某设计服务公司。约定设计课程宣传页，交付设计稿及可编辑源文件，总价 5,000 元，甲方先付 2,500 元，验收后付余款。确认需求后十个工作日内交初稿，甲方确认修改意见后完成最终交付。合同节选、付款记录沿用预览素材。

补充共同可读的沟通记录，D 表示需求确认后的工作日编号。

- D0，双方确认需求，乙方确认收到预付款。
- D8，乙方发 JPG 初稿，甲方提出字体、配色两项修改。
- D9，乙方确认收到意见并表示可以修改，尚未约定最终交付日期。
- D12，甲方要求先取得可编辑源文件；乙方表示修改尚未完成，最终稿验收后交付源文件。
- D13，甲方提出解除合作、返还预付款；乙方表示已完成初稿并愿继续修改，反对全额退款。

争点为“现有材料能否支持甲方此时要求返还全部预付款”。甲方强调交付不完整，乙方强调初稿按约提交且愿继续履行。底稿没有最终交付日期、特殊退款条款和实际损失金额，AI 须说明记录缺失，不能新增通知、合同或款项。

短练固定案卷包含合同节选、付款记录和沟通记录三项，学生可以写材料编号。预览资源与运行案卷分开维护；正式提交和证据披露属于较长训练的待办。

### 6.2 每幕行为

| 阶段     | 学生看到什么               | 学生能做什么                 | AI 依据与回应                                      | 推进条件               |
| -------- | -------------------------- | ---------------------------- | -------------------------------------------------- | ---------------------- |
| 准备     | 简报、争点、材料、角色选择 | 阅读、选边、问导师、开始     | 导师解释任务，法官开场                             | 选立场并开始           |
| 主张陈述 | 目标“说清请求和理由”       | 提交请求与事实依据、补充     | 对方说明固定抗辩，法官归纳分歧                     | 双方发言后学生结束阶段 |
| 材料讨论 | 材料列表与编号             | 引用材料、说明支持什么、回应 | 对方指出初稿与最终交付不同、日期缺失，法官聚焦约定 | 一轮后学生继续或结束   |
| 简短辩论 | 双方主张摘要与笔录         | 论证、反驳、返回材料讨论     | 对方依既定立场回应，法官区分已知与推断             | 一轮后学生结束         |
| 最后意见 | 目标“总结请求与主要理由”   | 总结、说明尚不确定部分       | 对方给最后意见，法官作教学性小结                   | 学生确认完成并保存     |
| 复盘     | 维度反馈、原话、提示情况   | 看笔录、重练、练题、回课程   | 评价器列优点、遗漏与下一步                         | 按选择进入课程或新活动 |

原告表达示例为“我请求返还预付款，理由是源文件仍未交付；但合同只明确初稿期限，我还需要说明为何 D13 已能要求全额返还”。评价关注是否发现材料缺口，不预设唯一裁判答案。换边时交换学生与对方角色，共同材料和目标保持同一版本。

### 6.3 必须覆盖的分支

以下是较长样例的目标行为，未实现能力以第 2 节为准；恢复和重练优先复用现有运行记录，不要求另建一套庭审会话。

| 情况             | 系统行为                                                                     |
| ---------------- | ---------------------------------------------------------------------------- |
| 陈述完整         | 对方针对理由回应，法官归纳，学生继续或推进                                   |
| 遗漏关键点       | 法官提一个聚焦问题，导师可定位材料，学生仍可结束阶段                         |
| 答非所问         | 提醒目标并给重新表达机会，保留原发言，提供结束练习入口                       |
| 引用未知事实     | 对方说明材料中未见，导师提示回查，原话记录为当事人说法                       |
| 请求提示         | 导师独立回答，正式轮次保持，不自动公开                                       |
| 回应失败         | 保留输入并重试本轮，同一命令不新增第二条学生发言                             |
| 刷新/断线/多标签 | 从已确认记录恢复，处理过期写入并保留草稿                                     |
| 保存返回         | 保存阶段与返回位置，下次显示继续演练                                         |
| 提前结束         | 确认后标记未完成阶段，仅评价已发生部分                                       |
| 重练             | 建立可区分的新一轮练习记录，优先复用 epoch；历史笔录与反馈的查看入口另行实现 |

### 6.4 运行中的短练

本样例故意保留事实缺口，适合训练“识别还缺什么依据”，不适合未经法学内容复核就作为具有唯一标准裁判答案的法考评分题。

| 环节       | 学生操作与系统行为                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------ |
| 入口       | 学生问“合同解除有什么条件？为什么违约时不一定能要求全额退款？”；先解释问题结构，再推荐一个短案例 |
| 案情       | 给出合同交付安排、D8 初稿、D13 退款请求等必要材料，目标只聚焦退款请求的依据与事实缺口            |
| 独立判断   | 学生写请求能否得到支持、理由与仍需确认的信息；不先展示参考答案                                   |
| 一次反驳   | 对手指出约定的初稿期限与最终交付不同，要求学生回应；不新增沟通或损失事实                         |
| 修正答案   | 学生区分已知事实、自己的推断与仍缺材料，重新写出理由                                             |
| 反馈与返回 | 导师解释论证缺口，回到原知识点；若要验证迁移，再使用另一个有明确规则与评分要点的题目             |

以上是短练的操作路径，指定问题已覆盖自动选择的确定性测试。对手的具体后续反驳和学生是否修正答案仍取决于实际对话。变式题可另做，当前不会自动弹出。

| 情景角色与导师 | lib/pbl/v2/agents/simulator.ts、instructor.ts                                              | 共同材料、职责、短练成本；其他情景维持既有行为        |

## 8. 验收与现状边界

### 8.1 已有代码及历史验证

题库第一阶段和 React 法庭工作区已存在；2026-11-05、2026-11-09 的历史试用记录分别覆盖题库基础与手工选择情景后的展示。它们没有证明普通知识点能自动调用法庭脚本。

2026-11-19 的回归验证使用固定案例和模型替身覆盖经典、Pro、Pi 推荐、情景字段、案卷一致性、短练启动与专用评价。启动测试另用隔离的内存数据库验证跨账户读取原课堂、另存练习、重复进入和过期案卷拒绝。未用真实模型重放用户课堂；实际推荐率、耗时、学生使用意愿与学习收益仍待验证。

### 8.2 建议的最小验收

- 普通知识点需求可以得到有理由的短练建议；不适合或材料不足时有清楚的普通练习路径。
- 经典、Pro 及课堂问答各自覆盖自己的选择与启动链路；不要仅用单个视图测试代表全链路。
- single-call 和多步 Planner 保留相同活动语义与展示配置，必要脚本确实进入相关调用。
- 学生与 AI 依据同一材料版本；评价能引用学生独立作答和匹配的规则、事实。
- 学生可以跳过，经阶段推进完成后返回原课堂；验证刷新续练和返回行为，完成不自动表示掌握。
- 提示、对手立场和参考解释清楚区分；普通面试、谈判等情景不受法律专用规则污染。
- 在可接受的等待和学习时间内完成；以新题独立表现验证价值。
- 旧课、重练、导入导出及两种题型反馈保持兼容。
